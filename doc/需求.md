# HorseNap v0.1 产品需求文档

## 1. 产品概述

**产品名称**

* 中文：牛马小憩
* 英文：HorseNap

**产品定位**

HorseNap 是一款轻量、开源、跨平台的桌面工位暂离告示软件。

用户暂时无法正常回应他人时，可以通过 HorseNap 在电脑屏幕上展示自定义信息、图片和倒计时，让路过工位的人立即知道：

1. 用户目前处于暂时不可用状态；
2. 用户为什么暂时无法回应；
3. 用户预计什么时候恢复。

适用场景：小睡 / 短暂休息、去洗手间、买咖啡、吃东西、去会议室开会、离开工位处理事情、短暂放空，以及其他用户自定义的暂离场景。

核心理念：

> **让短暂的暂离变得可见、明确，并减少不必要的误解。**

# 3. 产品界面

软件启动后进入主窗口，采用 **左侧工具栏 + 右侧实时预览** 布局。

## 3.1 左侧工具栏

提供三个功能：

### 模板选择

模板采用 **分类 → 模板** 两级架构：

* **分类层**：对应暂离场景，如 工作小憩 / 参加会议 / 外出买咖啡 等；
* **模板层**：分类下的风格变体，如 工作小憩 下的 轻松活泼 / 严肃认真 等。每个模板定义一组默认的大标题、副标题、理由说明和图片，可绑定倒计时样式与默认时长。

模板是内容预设：应用模板即把其默认内容写入当前配置，之后用户仍可逐项编辑。

应用规则：

* `contentModified`：标题、副标题、理由或图片任一项偏离当前模板默认时置为 `true`。
* 内容未被编辑过（`contentModified = false`）：直接覆盖。
* 内容已被编辑过（`contentModified = true`）：提示将覆盖已编辑内容，确认后覆盖。

v0.1 提供以下分类，每个分类至少一个模板（模板自带默认标题、副标题、理由与图片）：

| 分类 | 模板 | 默认标题 | 默认副标题 | 默认理由 | 图片 |
| --- | --- | --- | --- | --- | --- |
| 工作小憩 | 轻松活泼 | 人类防猝死计划执行中 | 马儿非常累，需小憩片刻，如有急事，请打醒我，非急事请勿扰 | 我已经加班加点地完成了阶段性的工作，现在极端困倦，需要短暂休息 {duration}。小憩之后，我会满血归来。 | 熟睡白马 |
| 参加会议 | 轻松活泼 | 会议室开会中 | 人在会议室，消息会回复得慢一些 | 我正在开会，预计 {duration} 后回来。 | 熟睡橘猫 |
| 外出买咖啡 | 轻松活泼 | 咖啡续命中 | 下楼买杯咖啡，很快回来 | 我去买咖啡，预计 {duration} 后回来。 | 熟睡白马 |
| 去洗手间 | 轻松活泼 | 暂离工位，很快回来 | 去个洗手间，稍后就回 | 临时离开一下，预计 {duration} 后回来。 | 熟睡橘猫 |

说明：

* 第 6、7、11 节的内容即"工作小憩 / 轻松活泼"模板的默认文案与素材；
* v0.1 模板复用两套预设插画（熟睡白马 / 熟睡橘猫），不新增插画资源；
* 每个模板的文案与名称均需提供 12 语言版本（见第 21 节）。

### 语言切换

提供 12 种语言切换入口（见第 21 节）。

### 关于

显示名称、版本号、GitHub 项目地址、开源许可证（MIT）、项目简介。

## 3.2 主窗口与编辑方式

* 主窗口为左侧工具栏 + 右侧预览；
* 点击预览中的区域，打开对应的**编辑面板（浮层）**进行编辑，预览实时更新；
* 编辑不在缩放预览内部进行内联编辑；
* 可编辑项：标题、副标题、理由、图片、倒计时。

# 4. 展示布局

预览与全屏使用同一套展示组件，预览按最终全屏布局等比缩放。

```text
┌────────────────────────────────────────────┐
│              大标题                          │
│              小副标题                        │
├─────────────────────┬──────────────────────┤
│                     │      倒计时区域       │
│                     │                      │
│                     ├──────────────────────┤
│      图片区域        │                      │
│                     │      理由说明         │
│                     │                      │
└─────────────────────┴──────────────────────┘
```

区域规则：

* 标题区：位于顶部，占满整行，包含大标题与小副标题；
* 图片区：占满整个左下块；
* 右下块：上下两部分，上半为倒计时，下半为理由说明，各占一半并占满右下。

布局使用 CSS Grid 实现：

```css
.layout {
  display: grid;
  grid-template-columns: 1fr 1fr;
  grid-template-rows: auto 1fr;
  grid-template-areas:
    "header header"
    "image  side";
}
.side {
  display: grid;
  grid-template-rows: 1fr 1fr;
  grid-template-areas: "countdown" "reason";
}
```

左右两列比例可随屏幕比例响应式调整，但始终保持"图片独占左下、倒计时与理由上下平分右下"。

# 5. 响应式设计

主要场景为横屏显示器，默认优先支持 16:9、16:10、21:9，并尽可能支持 4:3、较小窗口、高 DPI 显示器，以及 Windows / macOS / Ubuntu 不同缩放比例。

设计原则：

* 不依赖固定像素布局，使用 CSS Grid / Flexbox；
* 图片保持正确比例；
* 文字避免溢出；
* 倒计时始终保持显眼；
* 全屏状态尽可能利用可用屏幕空间；
* 屏幕比例过窄时允许合理压缩，不出现遮挡。

最小支持分辨率：1280 × 720。预览可读性按该分辨率的 1/4 缩放校验字号下限。

# 8. 倒计时

倒计时是展示页面的核心元素之一。用户在预览中点击倒计时区域打开设置面板（见第 10 节）。全屏展示为只读，不响应任何点击与编辑。

默认倒计时：

> **20:00**

默认样式：

* 灰色 / 深灰色背景；
* 红色数字，非常醒目；
* 有一定立体感，类似电子设备 / 数字仪表；
* 与蓝黑色夜间主题协调。

---

# 9. 第二套倒计时样式

> **沙漏倒计时**

* 沙漏图形，沙子随时间逐渐减少；
* 同时显示剩余时间（`19:42` 或 `19 min 42 sec`）；
* 剩余时间数字与真实倒计时精确同步；
* 沙子下降允许离散分段近似（如按剩余比例分 12 段），不需逐帧模拟真实沙流。

# 10. 倒计时设置

预览中点击倒计时区域，打开设置面板：

* **时长**：分钟直接输入，范围 1–180，并提供快捷预设 5 / 10 / 15 / 20 / 30 / 60 分钟；
* **样式**：数字仪表 / 沙漏。

生效规则：

* 计时器未运行（空闲态）：修改立即写入配置，下次展示生效；
* 计时器运行中（预览计时态）：修改立即写入配置；修改时长时以"当前时刻 + 新时长"重算截止时刻，修改样式不影响计时。

设置面板提供「停止计时」操作，仅在预览计时态 / 全屏展示态可用（见第 19 节）。

# 11. 理由说明

默认文案：

> **我已经加班加点地完成了阶段性的工作，现在极端困倦，需要短暂休息 {duration}。小憩之后，我会满血归来。**

规则：

* 配置保存理由的**原始文本**，其中 `{duration}` 为占位符；
* 展示时把 `{duration}` 替换为当前时长的本地化文本（如中文"20 分钟"、英文"20 minutes"）；
* 用户编辑理由时保留 `{duration}` 则继续联动，删除则不再联动；
* 该联动不受语言切换影响。

理由文案可自由修改，因此不仅用于睡觉，也可用于去厕所、买咖啡、开会、吃饭、临时离开等场景。

# 13. 图片选择

图片区域可点击（打开图片选择面板），提供两种方式：

### 预设图片

* 🐎 熟睡白马
* 🐱 熟睡橘猫

### 用户上传

允许用户选择自己的图片。上传成功后，应用将图片复制（导入）到应用数据目录，配置记录导入后的相对路径，原始文件之后被移动或删除不影响展示。切换图片后删除不再被引用的旧副本，启动时扫描并清理应用数据目录中的孤儿文件。

支持格式：SVG、PNG、JPG / JPEG、GIF（按浏览器原生方式循环播放）、WebP。类型按文件头魔数识别，与扩展名不符即拒绝导入。

导入限制（超出则拒绝并提示）：

* 单张图片 ≤ 10 MB；
* 位图单边像素 ≤ 8192；
* SVG 文件 ≤ 2 MB，且清洗后节点数 ≤ 5000。

用户上传的 SVG 必须经过清洗后才能使用（见第 23 节）。

# 14. 主题视觉

v0.1 使用固定主题，不提供主题切换：

> **蓝黑色 / 夜晚 / 睡眠**

视觉元素：深蓝、蓝黑、深灰、柔和白色文字、红色倒计时、少量暖色点缀。

背景加入少量**闪烁的小星星**：

* 缓慢、柔和、随机闪烁；
* 不影响文字阅读，不造成视觉疲劳。

整体效果：安静的夜晚 + 星空 + 熟睡的动物，而不是游戏 HUD 或高亮科技风。

# 15. 全屏功能

主界面右下角提供「全屏」按钮，以及「显示范围」选择（见第 19.4 节）。

点击后进入全屏展示状态（生命周期见第 19 节）。全屏页面**只读**，只显示展示内容，不显示也不响应工具栏、设置、窗口边框、编辑控件及任何鼠标点击。

最终效果：一张**巨大的数字化工位暂离告示牌**。

---

# 16. 退出全屏

全屏展示期间：

> **按任意键盘按键 / `Esc` 退出全屏。**

规则：

* 仅响应物理键盘按键（含 `Esc`）；鼠标点击不退出，避免路过者误触导致告示消失；
* 退出展示是非破坏性的：计时器不重置、继续运行，用户可再次点击「全屏」以剩余时间继续展示；
* 全屏窗口焦点被系统级操作抢占时，可通过托盘菜单「退出展示」作为兜底。

---

# 17. 防止系统进入休眠

全屏展示期间，HorseNap 主动向操作系统请求保持系统活动，防止因空闲导致：显示器自动关闭、系统自动睡眠、显示状态降低，以及屏保被空闲触发。

> 规范表述：Prevent system idle, display sleep, and automatic suspend while fullscreen mode is active.

分平台实现：

* **Windows**：Windows 电源管理 API（如 `SetThreadExecutionState`）；
* **macOS**：idle sleep / display sleep 抑制机制（如 IOPMAssertion）；
* **Ubuntu**：按当前桌面环境与系统能力实现 inhibit / power management（X11 / Wayland、GNOME / KDE 等）。

---

# 18. 系统能力边界

产品要求定义为：

> **在操作系统允许的情况下，HorseNap 在全屏展示期间阻止因系统空闲导致的显示器关闭、屏保触发和睡眠。**

即仅抑制"因空闲触发"的行为，不修改或禁用用户/系统已配置的屏保与电源策略。

以下情况超出应用控制范围，不作承诺：用户主动锁定电脑、主动关闭显示器、合上笔记本、公司 IT 管理策略、操作系统强制休眠、主动切换用户。

# 19. 全屏期间的应用行为

## 19.1 生命周期状态机

状态：

* **空闲态 Idle**：配置已保存，计时器未运行，无全屏窗口，主窗口可见；
* **预览计时态 Preview**：无全屏窗口，主窗口可见，计时器运行中；
* **全屏展示态 Displaying**：全屏窗口存在，主窗口隐藏，计时器运行中；
* **已结束态 Finished**：倒计时归零，计时器停止，全屏画面切换为到点文案（如"休息时间到了"）。

状态转移：

| 起始状态 | 事件 | 目标状态 | 结果 |
| --- | --- | --- | --- |
| Idle | 点击「全屏」 | Displaying | 记录 `T_ref = 当前时刻`，按显示范围创建全屏窗口，启动电源保持请求 |
| Preview | 点击「全屏」 | Displaying | 沿用既有截止时刻，不重置计时，按显示范围创建全屏窗口 |
| Displaying | 任意键盘键 / Esc / 托盘"退出展示" | Preview | 销毁全屏窗口、显示主窗口，计时器继续运行 |
| Displaying | 倒计时归零 | Finished | 计时器停止，播放一次提示音，全屏画面切换为到点文案，不自动退出全屏 |
| Displaying | 托盘"停止计时" | Idle | 销毁全屏窗口、显示主窗口、停止计时、释放电源保持请求 |
| Finished | 任意键盘键 / Esc / 托盘"退出展示" / 托盘"停止计时" | Idle | 销毁全屏窗口、显示主窗口 |
| Preview | 倒计时归零 | Idle | 计时器停止，预览恢复显示配置时长 |
| Preview | 点击「停止计时」/ 托盘"停止计时" | Idle | 计时器停止，预览恢复显示配置时长 |
| 任意运行态 | 托盘"退出应用" | 进程结束 | 释放电源保持请求后退出进程 |
| 任意状态 | 关闭主窗口 | 状态不变 | 隐藏到托盘，进程与计时器继续 |

到点行为：归零瞬间播放一次提示音，并将全屏画面切换为到点文案（如"休息时间到了"）；不发送系统通知，也不自动退出全屏。

说明：v0.1 不存在"不全屏即单独开始计时"的入口，Preview 只能由 Displaying 退出得到。

## 19.2 系统托盘

托盘图标全局唯一。

* **Windows / Linux**：左键单击显示 / 隐藏主窗口，右键弹出菜单；
* **macOS**：菜单栏图标单击弹出菜单，菜单内提供"显示 / 隐藏主窗口"。

菜单项（各平台一致）：显示 / 隐藏主窗口、进入展示（等同于「全屏」）、退出展示（回到预览，计时继续）、停止计时（回到空闲态）、退出应用。

* 关闭主窗口默认隐藏到托盘，不退出进程；退出只通过托盘菜单（macOS 上 `Cmd+Q` 等同于退出应用）。

## 19.3 计时基准与停止行为

* 倒计时基于 `T_ref + duration` 的绝对截止时刻计算剩余时间，不依赖逐秒累加，长时间运行不漂移；
* 退出全屏后倒计时继续，在预览中持续显示剩余时间；
* 停止倒计时的途径只有三种：点击「停止计时」/ 托盘"停止计时"、倒计时归零、退出应用；
* 不使用双击等隐式手势停止计时。

## 19.4 多显示器

显示范围设置：

* **全部显示器**（默认）：为每个显示器各创建一个无边框全屏窗口，内容完全一致；
* **指定显示器**：仅在用户选中的显示器上创建全屏窗口。

规则：

* 退出展示时销毁全部展示窗口；
* 所有窗口共享全局 `T_ref`，由截止时刻减当前时间得出剩余时间，绝不各窗口独立计时；
* X11 / Windows / macOS：展示期间新接入的显示器立即加入展示，拔出后其窗口销毁；
* **Wayland：不支持「指定显示器」，且展示期间不响应显示器变化；多显示器行为以进入展示时的显示器快照为准，需变更显示器须退出并重新进入展示。**

## 19.5 其他全屏行为

* 进入全屏 2 秒后隐藏鼠标指针，任何鼠标移动立即恢复显示；
* 进入全屏即发起保持活动请求，退出展示或退出应用时释放；
* 合盖、锁屏、切换用户等系统级行为超出应用控制范围。

# 21. 国际化（i18n）

支持语言（12 种）：

> 简体中文、繁體中文、English、한국어、日本語、Русский、Tiếng Việt、हिन्दी、العربية、Français、Deutsch、Español

语言选择：

* 首次启动按系统语言自动匹配，未命中回退英语；
* 之后以用户手动选择为准，并持久化。

覆盖范围：

* **UI 文案**（菜单、设置面板、提示、通知、关于页）：vue-i18n，语言包为 JSON 文件；
* **模板文案**：每个模板提供 12 语言的标题 / 副标题 / 理由 / 分类与模板名称；应用模板时写入当前界面语言版本；`{duration}` 占位符规则（第 11 节）对所有语言生效；缺失语言回退英语；
* **模板文案与 UI 文案分开存放**：模板文案随模板数据打包，不放入 `locales/*.json`；
* **告示内容不随语言切换变化**：已写入配置的标题 / 副标题 / 理由属于告示内容，切换语言不覆盖、不翻译；如需其他语言版本的模板文案，重新应用该模板。

RTL：

* 使用 CSS 逻辑属性（margin-inline、padding-block 等），界面通过 `dir="rtl"` 整体镜像；
* 全屏布局保持对称，倒计时数字始终按 LTR 呈现。

字体：

* 使用系统默认字体栈，不打包大型 CJK / Arabic 字体，接受跨平台字形差异；
* 在缺少相应字体的系统上可能出现缺字形，属已知限制。

翻译流程：

* 语言包随仓库维护，作为社区贡献的一部分；
* 发布前进行字符串冻结（string freeze），冻结后只接受翻译修正，不再新增键；
* 12 种语言的 UI 文案与模板文案须在 v0.1 发布前完成，任一项缺失即回退英语并记为待办。

# 22. 数据存储

不需要服务器，所有配置保存在本地：

* 位置：各平台应用配置目录；
* 格式：单个 JSON 文件 `config.json`；
* 写入：临时文件 + 原子替换；
* 读取失败 / 解析失败：损坏文件备份为 `config.json.bak` 后回退内置默认配置并提示。

保存内容：

* 配置结构版本号 `version`；
* 用户自定义标题 / 副标题 / 理由（理由为含 `{duration}` 占位符的原始文本）；
* 内容是否被编辑标记 `contentModified`；
* 当前模板引用（分类 id + 模板 id）；
* 倒计时时长与样式；
* 当前界面语言 `locale`；
* 用户选择的图片（导入副本的相对路径）；
* 显示范围；
* 窗口设置（主窗口尺寸与位置、预览比例）。

不保存：账号、登录、云数据库、后端 API、用户行为统计。核心功能完全离线可用。

运行时状态（`T_ref`、剩余时间、窗口实例）不持久化，重启后进入空闲态。

「指定显示器」配置在进入展示时校验：若无法匹配到当前显示器，回退到「全部显示器」，清空失效 id 并提示用户重新选择。不保证「指定显示器」跨会话稳定，该限制为已知限制。

# 23. 安全要求

第一版开放用户上传 SVG，SVG 清洗为必做项：

* 在 Rust 侧使用 `sanitize_svg` 等库做白名单清洗，移除 `<script>`、事件属性（`on*`）、`foreignObject`、外部 `href` / `xlink:href` 引用、`iframe` 等；清洗失败即拒绝导入并提示；
* 清洗后追加限制：文件 ≤ 2 MB、节点数 ≤ 5000；
* 渲染时通过 `<img src>` / data URI 加载 SVG，浏览器不执行其中脚本，CSS/SMIL 动画仍可用；
* 启用 Tauri CSP，禁止外部资源加载与不必要的网络请求。

# 24. 性能要求

* CPU 占用低、内存占用低、长时间运行稳定、倒计时准确；
* 星星动画与动物呼吸动画不得使用高频 JavaScript 循环实现；
* 优先使用 CSS animation、SVG animation、transform、opacity 等 GPU-friendly 方案。

# 29. 无障碍

* 遵循系统 `prefers-reduced-motion`，在该模式下降低或停用星星闪烁与呼吸动画；
* 文字与背景保持足够对比度；
* 不依赖纯颜色传达信息；
* 主窗口可交互控件在键盘导航时具有可见焦点。

# 30. 验收标准

在参考机（4 核 CPU / 8 GB 内存 / 集成显卡 / 1920×1080）上测量：

* 全屏展示期间平均 CPU ≤ 5%，内存 ≤ 300 MB；主窗口空闲内存 ≤ 200 MB；
* 点击「全屏」到画面呈现 ≤ 500 ms；
* 连续运行 8 小时：内存增长 ≤ 10%，倒计时累计误差 ≤ 1 秒；
* 动画帧率 ≥ 30 fps；
* 全部界面语言下，主窗口与全屏均无文字溢出、无控件重叠；
* RTL 语言下界面正确镜像，且倒计时数字保持 LTR。

# 32. 异常处理

* 图片导入失败 / SVG 清洗失败：拒绝导入，保持原图片不变并提示；
* 展示中图片文件缺失或损坏：显示占位图并记录日志，不崩溃；
* 配置文件损坏或缺失：备份后回退默认配置；
* 保持系统活动请求失败：记录日志并继续展示；
* 多显示器热插拔异常：忽略无法创建的窗口，不影响其他显示器；
* 「指定显示器」配置失配：回退「全部显示器」并提示重新选择。

# 33. 产品体验目标

HorseNap 应让用户感到：

> **"我暂时不能工作/回应，但我没有消失；我已经把状态和预计恢复时间告诉大家了。"**

不应给人企业考勤软件、监控软件、摸鱼软件、生产力软件或复杂桌面管理工具的感觉，而应是一个：

> **轻松、幽默、有一点自嘲，同时非常实用的工位暂离告示牌。**

核心品牌语气：

> **HorseNap 🐴💤**
> **Let the tired workhorse take a little break.**
