# HorseNap v0.1 产品需求文档

## 1. 产品概述

**产品名称**

* 中文：牛马小憩
* 英文：HorseNap

**产品定位**

HorseNap 是一款轻量、开源、跨平台的桌面工位暂离告示软件。

用户暂时无法正常回应他人时，可以通过 HorseNap 在电脑屏幕上展示醒目的自定义信息、图片和倒计时，让路过工位的人能够立即知道：

1. 用户目前处于暂时不可用状态；
2. 用户为什么暂时无法回应；
3. 用户预计什么时候恢复。

软件适用于：

* 小睡 / 短暂休息
* 去洗手间
* 买咖啡
* 吃东西
* 去会议室开会
* 离开工位处理事情
* 短暂放空或恢复精力
* 其他用户自定义的暂离场景

HorseNap 的核心理念：

> **让短暂的暂离变得可见、明确，并减少不必要的误解。**

# 3. 产品界面

软件启动后进入主窗口。

整体采用：

> **左侧工具栏 + 右侧实时预览**

布局。

## 3.1 左侧工具栏

第一版提供三个功能：

### 模板选择

用于选择、管理和配置展示模板。

模板采用 **分类 → 模板** 两级架构：

* **分类层**：对应暂离场景，如 工作小憩 / 参加会议 / 外出买咖啡 等；
* **模板层**：分类下的风格变体，如 工作小憩 下的 轻松活泼 / 严肃认真 等，每个模板定义一组默认的大标题、副标题、理由说明和图片，可另行绑定倒计时样式与默认时长。

模板是**内容预设**，不是独立的展示引擎：应用模板即把其默认内容写入当前配置，之后用户仍可像现在一样逐项编辑其中任何元素。

v0.1 范围：

* 只实现"工作小憩"分类，以及其下唯一一个模板"轻松活泼"（即本文档第 6、7、11 节的默认文案与素材）；
* 但分类 → 模板的两级数据结构与选择界面框架必须在 v0.1 落地，未来新增分类、同分类下新增风格、国际化分类都不需要改动架构。

### 语言切换

提供 12 种语言的手动切换入口（见第 21 节）。

### 关于

显示：

* HorseNap 名称
* 版本号
* GitHub 项目地址
* 开源许可证
* 简单项目介绍

未来可以增加更多功能，但 v0.1 不做。

# 4. 右侧预览区域

右侧为实时展示预览。

预览内容按照最终全屏展示的布局进行缩放。

实现语义：预览窗内使用与全屏**完全相同的展示组件**，外层以 `transform: scale` 等比缩小，保证预览与全屏 1:1 同构（这也是多显示器内容一致的前提）。预览窗尺寸可在约 1/4 – 1/2 屏范围内调整；可读性按最小支持分辨率的 1/4 缩放来校验字号下限。

用户可以直接点击预览中的不同区域进行编辑。

主要区域：

```text
┌────────────────────────────────────────────┐
│                                            │
│            大标题                          │
│            小副标题                        │
│                                            │
├─────────────────────┬──────────────────────┤
│                     │                      │
│                     │                      │
│      图片区域        │      倒计时区域       │
│                     │                      │
│                     │                      │
├─────────────────────┴──────────────────────┤
│                                            │
│                理由说明                     │
│                                            │
└────────────────────────────────────────────┘
```

最终布局应能够根据不同屏幕尺寸自动调整。

# 5. 响应式设计

HorseNap 需要适应不同尺寸和分辨率的显示器。

主要使用场景为横屏显示器，因此默认设计优先考虑：

* 16:9
* 16:10
* 21:9

同时应尽可能支持：

* 4:3
* 较小尺寸窗口
* 高 DPI 显示器
* Windows / macOS / Ubuntu 不同缩放比例

设计原则：

* 不依赖固定像素布局；
* 使用 CSS Grid / Flexbox 等响应式布局；
* 图片保持正确比例；
* 文字避免溢出；
* 倒计时始终保持显眼；
* 全屏状态下尽可能利用可用屏幕空间。

如果屏幕比例过窄，应允许布局进行合理压缩，而不是导致内容互相遮挡。

# 11. 理由说明

默认文案：

> **我已经加班加点地完成了阶段性的工作，现在极端困倦，需要短暂休息20分钟。小憩之后，我会满血归来。**

文案与时长联动：

* 上述默认文案中的"20 分钟"按模板变量处理：用户调整倒计时时长后，文案中的分钟数自动同步为当前值；
* 用户一旦手动修改过理由文案，不再自动改动其中任何文字（包括其中的时间表述），系统不做强制统一。

因此它不仅可以用于睡觉，也可以用于：

> 去厕所、买咖啡、开会、吃饭、临时离开等。

# 15. 全屏功能

主界面右下角提供：

> **全屏**

按钮。

全屏页面只显示最终展示内容，不显示：

* 工具栏
* 设置
* 窗口边框
* 编辑控件

最终效果应该类似一张：

> **巨大的数字化工位暂离告示牌。**

# 16. 退出全屏

全屏展示期间：

> **按任意键退出全屏。**

同时建议支持：

> `Esc`

作为明确的退出方式。

如果用户点击鼠标，第一版不要求退出。

这样可以避免用户不小心点击屏幕导致 HorseNap 结束。

---

# 17. 防止系统进入休眠

全屏展示期间，HorseNap 应主动向操作系统请求：

> 保持系统处于活动状态。

目标是防止：

* 自动关闭显示器；
* 自动进入睡眠；
* 系统因空闲而降低显示状态；
* 屏幕保护程序因普通空闲时间触发。

不同操作系统分别实现：

### Windows

使用 Windows 电源管理相关 API。

### macOS

使用 macOS 系统提供的防止 idle sleep / display sleep 机制。

### Ubuntu

根据当前桌面环境和系统能力实现相应的 inhibit / power management 机制。

---

# 18. 系统能力边界

HorseNap 应尽可能保持屏幕活动，但不能承诺能够覆盖用户主动执行的所有系统操作。

例如：

* 用户主动锁定电脑；
* 用户主动关闭显示器；
* 合上笔记本；
* 公司 IT 管理策略；
* 操作系统强制休眠；
* 用户主动切换用户。

这些情况可能超出普通桌面应用能够控制的范围。

因此产品要求应定义为：

> **在操作系统允许的情况下，HorseNap 在全屏展示期间阻止因系统空闲导致的显示器关闭、屏保和睡眠。**

而不是承诺：

> “任何情况下都不会黑屏。”

---

# 19. 全屏期间的应用行为

进入全屏后：

```text
启动展示（单击全屏按钮）
   ↓
记录参考时刻 T_ref，广播给所有展示窗口
   ↓
全屏展示 + 倒计时运行 + 背景动画 + 请求系统保持活动
   ↓
任意键 / Esc（任一显示器窗口收到即可）
   ↓
退出全屏，回到预览窗，倒计时继续
```

## 19.1 生命周期状态机

* **空闲态**：配置已保存，计时器未运行；
* **展示态**：用户点击"全屏"→ 记录 `T_ref` 与 `duration` → 在全部显示器创建全屏窗口 → 启动电源保持请求；
* **预览态**：任意键 → 销毁全屏窗口、恢复主窗口，**计时器不重置、继续运行**；双击倒计时 / 倒计时归零 / 退出应用 → 回到空闲态，计时器停止；
* 主窗口点击关闭 → 隐藏到托盘，进程与计时器继续；托盘"退出应用"→ 停止计时、释放电源保持请求、进程退出。

倒计时归零后的提示音、"休息结束"画面、系统通知等仍为后续版本功能，v0.1 归零后画面保持 00:00 直至用户退出。

## 19.2 系统托盘

* 左键单击托盘图标：显示 / 隐藏主窗口；
* 右键菜单：打开主窗口、启动展示、退出展示、退出应用；
* "退出展示"是"任意键退出"的兜底路径（全屏窗口焦点被系统级操作抢占时使用）；
* 关闭主窗口的默认行为是隐藏到托盘，而不是退出进程；退出只通过托盘菜单发生。

## 19.3 计时基准与停止行为

* 倒计时基于 `T_ref + duration` 的绝对截止时刻计算剩余时间，单调时钟或对时均可，不依赖逐秒 `setTimeout` 累加，长时间运行不漂移；
* 退出全屏后倒计时继续，在预览窗中持续显示剩余时间——用户回到工位但同事尚未看到告示时，剩余时间仍然有效；
* 停止倒计时的途径只有三种：双击倒计时、归零、退出应用。

## 19.4 多显示器

* 启动展示时，为每个显示器各创建一个无边框全屏窗口，内容完全一致；退出展示时全部销毁；
* 所有窗口共享全局 `T_ref`，倒计时由截止时刻减当前时间得出，绝不各窗口独立计时；
* 展示期间新接入的显示器立即加入展示；拔出后其窗口自然销毁；
* 预览窗与全屏使用同一套展示组件，保证多屏内容一致。

## 19.5 其他全屏行为

* 进入全屏 2 秒后隐藏鼠标指针；任何鼠标移动立即恢复显示；
* 进入全屏即向操作系统发起保持活动请求，退出展示或退出应用时释放（见第 17 节）；
* 合盖、锁屏、切换用户等系统级行为仍超出应用控制范围（见第 18 节）。

---

# 20. 单实例运行

* 通过 Tauri single-instance 插件保证全局只有一个 HorseNap 进程：再次启动时不创建新进程，而是唤起并聚焦已有实例的主窗口；
* 若已有实例正处于全屏展示，再次启动仅聚焦预览窗，不重新开始一次展示，避免两个实例的倒计时与电源保持请求互相干扰；
* 托盘图标同样全局唯一。

# 21. 国际化（i18n）

支持语言（12 种）：

> 简体中文、繁體中文、English、한국어、日本語、Русский、Tiếng Việt、हिन्दी、العربية、Français、Deutsch、Español

语言选择：

* 首次启动按系统语言自动匹配，未命中回退英语；
* 之后以用户在左侧工具栏"语言切换"中的手动选择为准，并持久化到配置。

覆盖范围：

* UI 文案（菜单、设置面板、提示、通知、关于页）：使用 vue-i18n，语言包为 JSON 文件；
* 模板默认文案：每个模板提供 12 语言的标题 / 副标题 / 理由 / 分类与模板名称；应用模板时写入当前界面语言的版本；模板文案中的 `{duration}` 变量联动规则（见第 11 节）对所有语言同样生效；
* 用户已自定义的标题 / 副标题 / 理由属于告示内容而非 UI 文案：切换语言不覆盖、不翻译，保持原样。

RTL（阿拉伯语）：

* 布局使用 CSS 逻辑属性（margin-inline、padding-block 等）而非物理方向属性，界面层通过 `dir="rtl"` 整体镜像；
* 全屏展示布局保持对称，倒计时数字始终按 LTR 呈现。

字体：

* 使用系统默认字体栈（Segoe UI / SF Pro / Noto Sans / 系统 Arabic 字体等），不打包大型 CJK / Arabic 字体，接受跨平台字形差异。

# 22. 数据存储

HorseNap v0.1 不需要服务器。

所有用户配置默认保存在本地。

保存内容包括：

* 配置结构版本号 `version`（为未来配置迁移预留）；
* 用户自定义标题；
* 用户自定义副标题；
* 用户自定义理由；
* 当前模板引用（分类 id + 模板 id + 已修改标记）；
* 默认倒计时时长与样式；
* 当前界面语言 `locale`；
* 当前主题；
* 用户选择的图片（导入副本的相对路径）；
* 窗口设置。

不需要：

* 用户账号；
* 登录；
* 云数据库；
* 后端 API；
* 用户行为统计。

核心功能应完全离线可用。

# 23. 安全要求

由于第一版就开放用户上传 SVG，SVG 清洗是**必做项**，不再有"只允许 PNG/JPG"的备选方案：

* 在 Rust 侧使用 `sanitize_svg` 等库对上传 SVG 做白名单清洗，移除 `<script>`、事件属性（`on*`）、`foreignObject`、外部 `href` / `xlink:href` 引用、`iframe` 等；清洗失败即拒绝导入并提示用户；
* 渲染时通过 `<img src>` / data URI 方式加载 SVG——浏览器天然不执行其中脚本，且 CSS/SMIL 动画仍可工作，正好满足预设素材的呼吸动画需求；
* 启用 Tauri CSP，禁止外部资源加载与不必要的网络请求。

# 24. 性能要求

HorseNap 是一个轻量桌面工具，因此应尽可能降低资源消耗。

目标：

* CPU 占用低；
* 内存占用低；
* 动画流畅；
* 不产生持续高 CPU 占用；
* 倒计时准确；
* 长时间运行稳定。

尤其是：

> **星星动画和动物呼吸动画不能通过高频 JavaScript 循环实现。**

优先考虑：

* CSS animation；
* SVG animation；
* transform；
* opacity；
* GPU-friendly animation。

# 27. 核心数据模型

可以从一个非常简单的配置对象开始：

```typescript
// ---------- 模板（内置，随应用打包） ----------

interface TemplateCategory {
  id: string          // 'rest' | 'meeting' | 'coffee' | ...
  name: string
  templates: Template[]
}

interface Template {
  id: string          // 'rest-casual' | 'rest-serious' | ...
  name: string        // 轻松活泼 / 严肃认真
  title: string
  subtitle: string
  reason: string      // 可含 {duration} 变量
  image: { kind: 'preset'; id: string }
  countdownStyle?: 'digital' | 'hourglass'
  defaultDurationMinutes?: number
}

// ---------- 用户配置（持久化到本地） ----------

interface HorseNapConfig {
  version: number     // 配置结构版本，用于未来迁移

  locale: string      // 'zh-CN' | 'zh-TW' | 'en' | 'ko' | 'ja' | 'ru' | 'vi' | 'hi' | 'ar' | 'fr' | 'de' | 'es'

  template: {
    categoryId: string
    templateId: string
    modified: boolean   // 应用后用户改过任意内容即为 true
  }

  title: string
  subtitle: string
  reason: string

  durationMinutes: number

  image: {
    type: 'preset' | 'custom'
    id?: string         // 预设图片 id
    path?: string       // 导入到应用数据目录后的相对路径
  }

  countdown: {
    style: 'digital' | 'hourglass'
  }

  theme: {
    background: string
    stars: boolean
  }
}
```

v0.1 中 `TemplateCategory` 数组只包含"工作小憩"一个分类、一个模板，但两级结构与接口从第一天就存在。

这样未来增加更多模板时，不需要重构整个系统。

# 28. 产品体验目标

HorseNap 最终应该给用户一种非常明确的感觉：

> **“我暂时不能工作/回应，但我没有消失；我已经把状态和预计恢复时间告诉大家了。”**

软件不应该给人：

* 企业考勤软件；
* 监控软件；
* 摸鱼软件；
* 生产力软件；
* 复杂桌面管理工具；

的感觉。

它应该是一个：

> **轻松、幽默、有一点自嘲，同时非常实用的工位暂离告示牌。**

核心品牌语气：

> **HorseNap 🐴💤**
> **Let the tired workhorse take a little break.**
