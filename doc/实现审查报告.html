HorseNap 实现审查报告

对照 doc/需求.md · 审查范围：前端（Vue 3）与 Tauri/Rust 全部源文件 · 方式：静态审查（未运行 GUI）· 2026-09-30

总体结论

覆盖度约 80%。架构、状态机、数据模型、配置持久化与图片安全管线质量较高；问题集中在 「展示窗口能否真正显示」、「跨平台电源保持与 12 语言未落地」 以及 「视觉 / 交互细节偏离需求」。

一、严重问题（阻断核心功能）

阻断1. 展示窗口创建后从未 show()

src/display.ts 创建窗口时设 visible: false，之后只 resolve，全仓库不存在对展示窗口的 show() 调用；而 startDisplay 又会先隐藏主窗口。若窗口确未显示，用户点击「全屏」后屏幕将完全空白。

const win = new WebviewWindow(label, { ..., visible: false })
return new Promise<void>((resolve) => win.once('tauri://created', () => resolve()))

修法：在 tauri://created 后调用 win.show()，或直接使用 visible: true。建议优先实测确认。

阻断2. 非 Windows 平台因电源保持报错中断启动流程

src-tauri/src/power.rs 在 macOS / Linux 为 stub，直接返回 Err；而 startDisplay 中该调用未捕获：

await invoke('set_keep_awake', { on: true })  // §17
await broadcastSnapshot()

结果：非 Windows 下抛异常并跳过 broadcastSnapshot()，展示窗口拿不到 deadlineMs、倒计时不走，同时产生未捕获的 Promise rejection。既违反 §17 三平台要求，也是实际缺陷。

修法：按 §31「记录日志并继续展示」捕获异常，并补 macOS（IOPMAssertion）/ Linux（inhibit）实现或明确降级。

未完成3. 12 语言未交付（§21）

仅提供 zh-CN / zh-TW / en，其余 9 种语言 UI 与模板文案均回退英语。回退机制本身符合 §21 降级条款，但「12 语言须在发布前完成」未达成。

三、细节质量瑕疵（低）

  • 沙漏只显示 xx min，未提供需求示例的 19 min 42 sec（HourglassCountdown.vue）。
  • {duration} 兜底语义错误：无 Intl.DurationFormat 时回退 RelativeTimeFormat，会产出「in 20 minutes」，英文下变成「a short break of in 20 minutes」（i18n/index.ts）。
  • WebP 未校验像素上限：bitmap_dims 对 webp 直接返回 (1,1)，绕过 §13 的 ≤8192 限制（image.rs）。
  • 浏览器保留键未排除：注释称排除，实际对任何 keydown 都退出（display.ts）。
  • 健壮性：store.ts 的 loadConfig 使用 tpl! 非空断言，模板缺失时会抛错。
  • SVG 清洗用自写正则而非需求指定的 sanitize_svg 库；虽有 <img> 渲染作第二道防线，仍建议换成熟库（§23）。
  • 时长预设多出一个 45 分钟（需求外，无害）。

四、做得好的部分

  • 状态机与 §19.1 几乎逐条对齐：四态转移、Preview 沿用截止时刻、停止计时三条途径、到点不自动退出并播提示音。
  • 配置持久化规范（§22）：临时文件 + 原子 rename、写前校验 JSON、损坏备份 .bak 回退。
  • 图片安全管线完整（§13/§23/§32）：魔数识别、大小/像素限制、SVG 清洗、导入复制、孤儿清理 + 竞态保护。
  • 模板体系一致（§3.1）：4 分类 × 各 1 模板、contentModified 判定、覆盖前二次确认；{duration} 以原始文本存储并在渲染期插值（§11）。
  • 单实例（§20）、托盘菜单随语言下发（§19.2）、关闭隐藏到托盘（§19.2）均已实现。
  • 数据模型与 §28 完全对应，并将 deadlineMs 等归入运行时 DisplaySnapshot（不持久化）。
  • 动画全用 SMIL / 声明式，无常驻 JS 循环（§24）；展示只读、鼠标不退出、任意键盘键退出、2 秒隐藏指针均已落地。
  • 响应式使用容器查询单位 cqmin，符合 §5「不依赖固定像素」。

五、建议处理顺序

  1. 先实测确认 #1——点「全屏」后是否有画面；若确不显示，这是唯一的功能级阻断。
  2. 修 #2：set_keep_awake 加 catch，并补 mac/Linux 实现或明确降级。
  3. 决策 #5：语言切换是否改动告示内容，然后统一代码或文档。
  4. 补 #4 星空背景、#3 语言包、#8 点击预览编辑（或修订文档）。
  5. 顺手清理：托盘 Quit 死代码、README、{duration} 兜底文案、WebP 像素校验、window.confirm → dialog。
